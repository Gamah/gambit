# Audio

Board sounds, spoken moves, music, lobby chat and proximity voice.

## Board sounds

Synthesized WAVs in `client/Assets/sounds/sfx/`, generated by `scripts/gen_sounds.py` (numpy).
Treat its current output as intended. `.sound` files: `"Sounds"` lists `.vsnd` paths (not
`.wav`), `"Volume"`/`"Pitch"` are JSON strings, `"UI": true` for 2D playback, `"__version": 1`.
A 3D variant is a `.sound` with `"UI": false` pointing at the same `.vsnd`; it needs no second WAV.

`tick`/`tock` are move sounds (White/Black), once per move. `panic` is the only per-second sound.

**Every board sound goes through `Gambit.Audio.TableSounds`, which watches the `IBoardGame`
seam** (`BoardGame.Source( Controller, Lichess, Relay )`, the same expression `ChessBoardView` and
`GameHud` resolve). A local, lichess or relay game gets the same sounds because it is on the seam.
Never add a `Sound.Play` to a game controller; a reactive feature that reads
`LocalGameController` is wrong during a lichess or relay game.

| Moment | Sound | Yours (2D) | The room's (3D) |
|---|---|---|---|
| Move | `tick` (White) / `tock` (Black) | ✅ | ✅ `tick3d`/`tock3d` |
| Capture | `pop` | ✅ | ✅ `pop3d` |
| Check | `check` | ✅ | ❌ the king is already tinted red |
| Game over (incl. a flag) | `gameover` | ✅ | ✅ `gameover3d` at 45% |
| Draw / takeback offered | `offer` | ✅ | ❌ only the player being asked |
| Clock under `TimeControl.PanicSeconds` | `panic`, 1/sec | ✅ | ❌ |
| lichess TV game ends | `gameover3d` | — | ✅ at the north wall (`SpectatorController`) |
| Ring rebuild | `slide_servo_*`, follows the cabinet, unoccluded | — | ✅ (`ChessStation`) |
| Settings click | `tick` | ✅ | — |

Your table is 2D, the room's tables are 3D, and the room must stay quiet with six tables live.
The gates are `PlayerData.MyCabinetSounds` / `RemoteCabinetSounds` (the BOARD SOUNDS row), both
default true. **Which sounds cross the room is decided in `SoundPlayer`**: each method takes
`mine` rather than letting the caller pick the 2D or 3D asset.

There is no flag sound (a flag is a game over) and no sound for resign beyond game over, or for
sitting and standing.

**No sound may be fired from a FEN diff alone.** A FEN change also means a takeback, a table reset
or a late joiner's first sync; only the ply direction separates those from a move.
`Code/Chess/BoardDiff.cs` classifies a change as `Move` / `Rewind` / `None` and is Sandbox-free,
so it runs in a dotnet harness.

## Spoken moves

BOARD SETTINGS' SPEAK MOVES AT MY BOARD reads out moves played at the board you are seated at,
never the TV wall or another table. `TableSounds` calls `MoveTts.SpeakLastMove(game)` only when
`Mine`, so it inherits the move classification and covers every game type (`ChessBoard.Move` fills
SAN on execution). `Code/Chess/MoveSpeech.cs` turns SAN into words and is Sandbox-free.

- `Sandbox.Speech.Synthesizer` is SAPI-backed and Windows-only. Elsewhere it has no voices and
  `MoveTts` is a silent no-op; every path fails closed to silence.
- `MoveTts.Voices` is enumerated once and cached: constructing a `Synthesizer` queries the OS and
  the settings panel rebuilds its rows every frame. Each speak constructs a fresh one (its text
  can't be reset) and synthesizes on the main thread, only when the feature is on.
- The voice picker is a tap-to-cycle pill storing the full name (`TrySetVoice` needs it) and
  showing a short one.

## Music

The `gamah.skafinity` library (`client/Libraries/gamah.skafinity/`, see `docs/setup.md`). Player
and panel are built client-local by `LocalMusicSystem`, never scene-authored.

The music board is keys, not a wall (`UI/MusicScreen.cs`): **N** opens it while roaming (engaged
already owns the screen and Escape), **M** mutes anywhere. Both are raw `Input.Keyboard` checks.
The panel stays disabled while closed, because its floating ♪ button is a pointer-events element
that would hold the cursor and kill roaming mouselook. While open, `Mouse.Visibility` is
`Visible` (which also zeroes `Input.AnalogLook`, so clicking can't spin the camera); every exit
(✕, Escape, N, engaging, `OnDisabled`/`OnDestroy`) restores `Auto`.

## Lobby chat

The engine draws chat: `ChatShowUI` is `true` in `ProjectSettings/Platform.config`. Do not add a
custom chat box. The chat window's position and size belong to the engine's menu addon
(`ChatOverlay`) and `Platform.config` exposes only `ChatEnabled`/`ChatShowUI`/
`ChatMaxMessageLength`, so the window cannot be moved from game code.

`ChatPanel.IsOpen` is a stub `=> false`, kept so `LobbyPlayer`'s "don't walk while typing" gate
compiles; the engine's focused text box already stops WASD. `ChatPanel` draws nothing and cannot
be deleted without orphaning its `lobby.scene` entry.

`UI/Screens/HudHints.razor` is the one bottom-left keycap stack: Chat · M mute music · N music ·
G voice · B mute players. The Chat keycap reads its binding live (`Input.GetButtonOrigin( "Chat" )`);
M/N/G/B are raw keyboard checks in `MusicScreen`/`VoiceScreen` and are spelled out, so keep them
in step. There is no glyph-icon API, so a keycap is the binding string in a box. `VoicePanel`'s
mute roster opens above the stack (`bottom: 100px` vs `44px`); keep the two in step and add no
third tenant to that corner.

`PlayerData.GamepadBindings` is real; there is no keyboard `Bindings` store.

## Proximity voice

`GambitVoice` (a `Voice` subclass) rides every avatar, added host-side in
`LobbyNetworkManager.AddVoice` before `NetworkSpawn`. `VoiceScreen` (keyboard driver),
`VoicePanel` (mute roster) and `HudHints` self-attach to the ScreenPanel, so mute and enabled
state (cookies in `Gambit.Game.VoicePrefs`) never ride a snapshot. Voice defaults off.

- **Playback gates on the receiver**: `ShouldHearVoice(Connection c)` is called with the sender's
  connection and returns `VoiceEnabled && !IsMuted(c.SteamId)`, so mute needs no sync or authority.
- **Transmit is gated owner-locally via `Voice.Mode`**: on = `AlwaysOn` with the `"Voice"` binding
  as `PushToTalkInput`; off = `Manual` with the unbound `NoVoiceInput` sentinel. Never touch a
  networked Enabled flag.
- **Hearing range is receive-side.** Falloff is applied on the receiver from each proxy's
  `Voice.Distance`, so `VoiceScreen.ApplyHearingRange` writes `Distance` onto every avatar's voice
  each frame from the local player's engage state: `PlayerData.VoiceRangeAtTable` seated,
  `VoiceRangeRoaming` otherwise. Both are sliders on the world-settings board.
- The default `Falloff` is front-loaded (~4% by 20% of range), so voices use a linear `Curve` and
  `Volume = 2f`. The default `Distance` (15,000u) is wrong for an 800u room.
- `Voice.OnUpdate` is sealed; only the hear/exclude hooks are virtual.
- V is the engine's push-to-talk (the `"Voice"` action), so the master toggle is **G** and the
  mute roster is **B** (roaming only). `Voice.IsListening` honours the user's s&box `voip_mode`,
  which game code can't change; the HUD chip reports it and never claims to be the switch.

## Settings sliders

Every continuous setting (brightness, pop rate, voice range, move-voice volume) is a
`SettingsModel.SliderSpec` rendered as a real `SliderControl` by whichever panel the row is on.
Sliders are continuous (no `Step`) and `OnChange` persists on every change. The label carries the
value and recomputes because `Mutate` bumps `SettingsVersion`; a `SliderControl` survives the
mid-drag rebuild because s&box diffs it. The vendored skafinity music sliders are the library's
own; leave them.

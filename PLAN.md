# PLAN.md

One flat table, ranked highest first. **A shipped row is deleted, not ticked**; when you close
one, put what a future session would get wrong without it into `CLAUDE.md` or `docs/`. Rows are
intentions, not specifications: a better idea beats the row, so change the row. The only hard
constraints are the canonical contracts named in `CLAUDE.md`.

| # | Row |
|---|---|
| 92 | **`LobbyPlayer.Update` and `SeatSettingsPlate.Update` throw every frame while seated**, with a render-tree NRE alongside, seen in the editor console. Get the stack first — the log beside `sbox-dev.exe` has it. Ruled out already: nothing in the VR work touches either path, and `SkinnedModelRenderer.Set`/`SetLookDirection`/`SetBodyGroup` all route through `SceneModel?.`, so the renderer the VR body hide disables is not it. Check `master` at a seat too; this may predate the branch, which decides whether it blocks a merge. |
| 88 | **The seated VR eye is the desktop camera's orbit point, not a seated head.** `VrRig` anchors the playspace so the real head lands on `ChessStation.SeatAnchor`, which at `ChessRing.SeatEyeBlend` 1 (the default) is the orbit point: ~80 units above the floor and ~32 back from the board centre, where the repo's own estimate of a seated eye is 49 (`SeatEyeBack`/`SeatEyeHeight`, both `[GUESS]`). One unit is an inch, so a seated player's eyes are about two feet too high. `SeatEyeBlend` 0 is the knob built for exactly this swap and touches nothing else by construction. Worth doing before anything is tuned by eye, because every judgement about panel size, reach and board scale rests on it. |
| 80 | **A VR UI that is not the desktop HUD on a quad.** The adopted screen layout is a 1920x1080 panel with a crosshair and keyboard hints, squared on the board and covering it; it is how a game gets started only because nothing else is. The pattern to copy is in the room already: wall-board sized panels built the way `WallBoardGeometry` builds them (`docs/vr.md`), placed at the table rather than in the view, reached by the beam. Open question the row does not answer: which controls belong in the world and which belong on a panel at all. |
| 74 | **Grab a piece with the grip and move it.** Grip is unused for exactly this (`VrInput`). It needs a pick that is a lift rather than a square-by-square select, a held-piece pose, and a drop that resolves to a square — all of it through the `ChessGame` legality seam the click path already uses, so the move never becomes a second rules path. It also retires a double duty: one trigger pull currently both clicks a panel and pulses `Select`, so a press on the quad can pick the square behind it. |
| 68 | **Hands, not boxes.** Both controllers are tinted dev cubes at the grip pose, because `VRController.GetModel` returns `models/dev/box.vmdl` for every device `[SOURCE]`. The end state is the citizen's own arm and fingers on IK — `LobbyPlayer.ApplyHandPose` already drives a seated arm from `Gambit.Chess.TerryPose` through `SetIk`, which takes a world transform and needs no GameObjects (`docs/terry.md`). The ray keeps coming off the controller transform wherever the animation puts the hand. |
| 60 | **Shadows flicker in VR only.** Never diagnosed. A shadow-casting sun moves every frame (`RoomLightOrbit`) plus four shadowed point lights, against a time-sliced shadow cache (`r.shadows.updates`, default 8) now serving three views. Ladder: `gambit_vr_companion` (drop the third view), `r.shadows.csm.enabled 0`, `r.shadows.updates 64`, `r.shadows.debug 1`. |
| 54 | **The hint copy has no VR branch.** Ten panels under `client/Code/UI/` name a key to a player holding two controllers — every wall board's "PRESS E", `InfoScreen`'s "Press E or Esc to close", the `HudHints` keycap stack — so this is wider than a string swap: it wants one place that answers "what does this control say right now", which does not exist yet. The two info boards are part of any change to how the world behaves (`CLAUDE.md`), and they are the two that must not be forgotten: `CenterInfoPanel.razor` and `InfoScreen.razor`'s Welcome branch. |
| 48 | **The music HUD is still flat in both eyes.** `LocalMusicSystem` builds its own `ScreenPanel` on a `NotSaved` object, which `VrHud.Adopt` never sees — it adopts the scene's UI object only. Either adopt every root panel in the scene or give that one a world panel of its own; the first is a rule, the second is a special case, and the choice is the row. |
| 40 | **No comfort options.** Turning is smooth only, at `VrInput.TurnRate` 110°/s off the right stick, with no snap option and no vignette, and the playspace re-anchors under the player on a seat capture. Snap turn is the one setting most VR players look for first. The settings seam exists (`BoardSettingsScreen`, `SettingsModel`), so the work is deciding what belongs there versus a console knob. |
| 30 | **Upstream: `button_b` never binds on an Index.** `game/core/cfg/fpxr/valve_knuckles.json` gives it a `paths` key holding a bare string, where every other `paths` in both shipped profiles is the per-hand object map and every single binding uses `path`. One character, `paths` → `path`, as a PR to sbox-public. Nothing here depends on it — Escape answers to A as well — and that repo's master is flaky, so verify only this. |

# PLAN.md — Terry's Gambit: what's left

How the game is built lives in **`CLAUDE.md`**, which indexes the four subject docs:
**`LICHESS.md`**, **`GAMCHESS.md`**, **`SBOX-NOTES.md`** and **`TERRY-HALFRISE.md`**. The
gamchess API contract lives in **`README.md`**. This file is only ever upcoming work.

**This is a list of things that need doing, ranked 1–100, highest first. Nothing else.**

- **`Pri` is a priority, not a schedule and not an order.** It says what would hurt most
  to leave undone, not what to do next. Nothing here blocks on the item above it unless the row
  says so.
- **`No.` is just a reference handle** — a short id to mention a row by ("do No. 5"). It is NOT
  priority and NOT stable across edits: rows are renumbered top-to-bottom whenever any is added
  or deleted, so a number names a row only within the current version of this file.
- **Rows are not branches.** Group them into whatever branches make sense when you pick them
  up — several small rows on one wall or one panel are usually one branch, and one big row
  (the viewer) is usually its own. The table is deliberately flat so it can be
  regrouped freely; do not read the ranking as a milestone plan.
- **Delete a row when it ships.** The reasoning that outlives the work belongs in CLAUDE.md;
  everything else belongs in git. If a row is only *recorded* — a decision not to do something —
  it says so, and it stays.
- Rows marked **room** need someone standing in the game. Nothing on this host can render or
  make a sound, so those cannot be closed by review.

| 0 | 99 | Puzzles in the Lichess tab | **The scopes are ALREADY GRANTED** — `puzzle:read puzzle:write` since 2026-08-05, so this costs no re-link, and it is the only lichess feature left that doesn't. Spec + lila re-derived **2026-08-13**. **Fetch:** `GET /api/puzzle/next` and `GET /api/puzzle/batch/{angle}?nb=1..50` (never-seen-before when authed; `difficulty` is `easiest…hardest` **relative to the player's own puzzle rating**, so there is **no rating chip and no `/api/account` call** — the `ratingRange` lesson again). **Report:** `POST /api/puzzle/batch/{angle}` with `{solutions:[{id,win,rated}]}` **moves their real lichess rating**, answering `rounds[].ratingDiff` + `glicko`, and with `?nb=` hands back the next batch in the same call. Also readable: `dashboard/{days}`, `activity` (ndjson — we have the reader), `replay/{days}/{theme}`. `daily` and `{id}` are **`security: []`**, so an unlinked player can still solve — the TV rule again. The solve runs **entirely on our board** against `solution[]` (UCI) under the vendored rules: no stream, no event-stream slot, no clock apparatus, nothing the M8 machinery is needed for. **The honesty rule, and lila enforces two thirds of it** (`PuzzleFinisher.apply`, lila master, **[SOURCE]**): a puzzle the user already has a round for is **never** rated whatever we send, and `rated:false` never rates — so replay-farming and re-rating are impossible from here. What lila **cannot** see is whether the player found the moves. So: `rated:true` **only** on a clean first attempt; anything assisted (hint, retry, peek, or our own `ChessEngine` sitting one file away) is `rated:false`; and **losses must be reported** — a client that only POSTs wins is a rating inflator with every other rule kept. Two modes, named in the UI, because a player who doesn't know which one they're in can't consent to the first. **Trap:** a puzzle is a fourth `IBoardGame`, so `BoardGame.Source` grows a fourth argument while **three call sites are still passing two** — the P99 hazard, live again. Settle early whether the room sees your puzzle (local-only = free; visible = host-folded FEN, i.e. real networking). The solve state machine is Sandbox-free → harness-provable on this host; the panel is **room**. Copy ships with it: `InfoScreen`'s Lichess branch must say that solving here moves the same number as solving on lichess.org. **Out of reach:** Storm and Streak have **no play API at all** (only a `security: []` storm *dashboard* read), and Racer needs `racer:write` plus the creator starting the race in a browser — a re-link for a link-out. |

| 4 | 45 | Wire up `opponentGone`, now that it can finally be true | **HTTPFIX made this answerable and deliberately did not do it.** On the Board API the open game stream IS presence — which is exactly why "make a roamed-away player's light go out" was stuck before: gamchess held the stream open continuously, so our player was ALWAYS present and lichess's `opponentGone` could never fire for them. Each client holds its own stream now, so a dropped client really does go absent. **Two halves, and only the first is free:** (a) INBOUND — `opponentGone` arrives on the game stream and `LichessGameController.Consume` ignores it with every other unknown type; showing "your opponent has disconnected" is small. (b) OUTBOUND — a player who ROAMS AWAY is still running the client and still holding the stream, so lichess still sees them present. That closes only if the client DROPS the game stream on stand-up (say ~10s of grace, so a trip to the fridge doesn't flap it) and re-opens on sit-down; a reconnect's `gameFull` carries the whole move list, so nothing is lost. **That is a product decision, not a consequence of the architecture** — it makes standing up mean "I've left", which M17 deliberately made it not mean. **Re-derive `opponentGone` from lila master before building either half**: that it fires for a Board API opponent who closes their stream is INFERRED, not read, and it is the load-bearing fact. Do not state a claim-window duration without reading one. |

| 10 | 6 | Talking to lichess about limits | **The premise changed and mostly evaporated.** This row existed because gamchess relayed every player's games from ONE IP, so lichess's per-IP limits were per-*playerbase* and the lobby seek's 5/min was 5/min for everyone alive.
